# NextBeat

Feedback-aware next-track recommendation · Holberton School ML final project

The question behind NextBeat is simple: does listening order tell the whole story, or does feedback help too? The project compares four recommendation approaches using anonymous Yambda listening histories.

## Run the application

1. Install Python 3.12 and extract the whole ZIP.
2. Open the `NextBeat` folder and double-click `start_windows.cmd`.
3. Keep the terminal open while using the application in your browser.

The first launch installs the required packages. The saved models are ready to use; opening the application does not train them again. Run `verify_windows.cmd` to check the installation and saved models.

For a manual setup on Windows:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python -m streamlit run app.py
```

On Linux or macOS, create the environment with `python3.12 -m venv .venv` and use `.venv/bin/python` for the remaining commands.

## Using NextBeat

Select an anonymous user and a model, then click **Recommend next tracks**. The table shows ten track IDs in ranked order. Keep the same user when comparing models. Scores are ranking values within each model, so their sizes should not be compared between models.

The optional feedback selector changes the last input event for a what-if comparison. It does not update the saved history, retrain the model, or change the evaluation results. Track titles and audio are unavailable in this dataset.

## Data and training

| Item | Count |
|---|---:|
| Selected users | 2,500 |
| Events in the selected cohort | 11,763,348 |
| Events before the training cutoff | 8,590,059 |
| Eligible training targets per epoch | 2,837,655 |
| Candidate tracks | 10,000 |
| Epochs per neural model and seed | 3 |

All events from the selected users are retained. The catalogue is selected using training data only. Events outside that catalogue remain in the input as an unknown track. The three epochs process 8,512,965 examples per neural model and seed; repeated examples across epochs are not additional unique targets.

## Results

The comparison includes Most Popular, ItemKNN, a sequence-only GRU, and NextBeat, which adds feedback to the same GRU architecture.

Across training seeds 42, 43 and 44, mean Recall@10 was 10.03% for NextBeat and 9.29% for the sequence-only GRU. Mean NDCG@10 was 0.0534 and 0.0519 respectively. NextBeat had higher NDCG in two of the three runs. This is a small, mixed advantage on one fixed split, not a consistent improvement on every metric.

The interface shows the original seed-42 results. It keeps the model selected by validation NDCG, rather than selecting a training seed using test results. All four models now score 0.000% dislike violations (NFVR) on the reported test-set metric, across all three training seeds — down from 0.312% for NextBeat and 0.272% for the sequence-only GRU before an inference-time filter was added that excludes any track a user actively disliked from every model's ranking. This reported figure is scoped to the batch evaluation, which checks a user's entire history; the live Streamlit app and API filter only within the same 20-event context window the model sees, so a dislike far outside that window is not guaranteed to be filtered live even though it is filtered in the reported metric.

Recall@10 and NDCG@10 use 994 eligible targets inside the catalogue. Recall over all 2,229 test targets also counts excluded targets as misses. See `docs/Methodology.md`, `REPEATED_SEEDS.md` and `experiments/seed_results.csv` for the protocol and full comparison.

## Reproduce training

Use a separate copy of the project if you want to preserve the delivered models. From that copy, using its virtual environment's Python:

```bash
python download.py
python run.py prepare --raw data/raw/multi_event.parquet --users 2500 --catalog 10000 --seed 42
python run.py train --epochs 3 --all-targets --seed 42
python repeat_seeds.py --seeds 43 44
python summarize_seeds.py
python -m pytest -q
```

Raw data and prepared training arrays are downloaded or generated by these commands and are not included in this archive. Preparation needs several GB of RAM. Training time depends on the machine. Small numerical differences between hardware and library kernels are possible.

## API and Docker

```bash
python -m uvicorn api:app --host 127.0.0.1 --port 8000
```

Endpoints: `/health`, `/users`, `/recommend/{uid}` and `/docs`.

```bash
docker build -t nextbeat .
docker run --rm -p 8501:8501 nextbeat
```

The Docker recipe is included but has not been build-tested. The project has not been evaluated with live users. The catalogue is restricted, and repeated-seed results share a previously inspected time split. NextBeat uses observable listening behaviour; it does not identify mood or know track titles or genres.
